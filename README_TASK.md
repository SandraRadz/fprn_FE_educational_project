# ФПрН API — специфікація ендпоінтів

Бекенд для сайту **Факультету природничих наук НаУКМА**. Готовий фронтенд уже звертається до ендпоінтів, описаних нижче. Щоб усі сторінки запрацювали, треба реалізувати саме їх.

Автентифікації та прав доступу немає: усі ендпоінти відкриті.

---

## Загальні домовленості

- **Бекенд:** `http://localhost:8000`
- **Фронтенд:** `http://localhost:5173`. Запити йдуть із цього origin.
- Усі шляхи починаються з `/api/` і **закінчуються слешем**, наприклад `/api/teachers/` і `/api/teachers/3/`.
- Тіла запитів і відповідей передаються в JSON (`Content-Type: application/json`).
- Списки повертаються **простим масивом**, без пагінації.
- Зв'язки між сутностями передаються як **id**, наприклад `"department": 2`, без вкладених об'єктів.

### Коди відповідей

| Операція                   | Успіх            |
|----------------------------|------------------|
| `GET` список / один об'єкт | `200 OK`         |
| `POST` створення           | `201 Created`, у тілі створений об'єкт з `id` |
| `PUT` оновлення            | `200 OK`, у тілі оновлений об'єкт |
| `DELETE` видалення         | `204 No Content`, тіло порожнє |

### Помилки

Фронтенд очікує саме такі формати.

- **`400 Bad Request`**, помилки валідації. Ключ — назва поля, значення — список повідомлень. Фронтенд показує їх під відповідними полями форми.
  ```json
  { "name": ["This field is required."], "email": ["Enter a valid email address."] }
  ```
- **`404 Not Found`**, об'єкта з таким `id` не існує.
- **`409 Conflict`**, видалення неможливе (див. кафедри). Фронтенд показує текст із поля `detail`.
  ```json
  { "detail": "Пояснення для користувача" }
  ```

## Сторінки фронтенду і що вони викликають

| Сторінка  | Що робить користувач                                | Ендпоінти |
|-----------|-----------------------------------------------------|-----------|
| Головна   | читає інформацію про факультет (статичний текст)    | — |
| Кафедри   | переглядає список, додає, редагує, видаляє          | `GET`, `POST /api/departments/`<br>`PUT`, `DELETE /api/departments/{id}/` |
| Викладачі | переглядає список, додає, редагує, видаляє; кафедру обирає з випадного списку | `GET`, `POST /api/teachers/`<br>`PUT`, `DELETE /api/teachers/{id}/`<br>`GET /api/departments/` |
| Курси     | переглядає список, додає, редагує, видаляє; кафедру й викладача обирає з випадних списків | `GET`, `POST /api/courses/`<br>`PUT`, `DELETE /api/courses/{id}/`<br>`GET /api/departments/`, `GET /api/teachers/` |

## Ресурс «Кафедри»: `departments`

### Поля

| Поле          | Тип     | Обмеження |
|---------------|---------|-----------|
| `id`          | integer | лише читання |
| `name`        | string  | обов'язкове, унікальне, до 200 символів |
| `description` | string  | необов'язкове, може бути порожнім рядком |
| `email`       | string  | необов'язкове, валідний email або порожній рядок |

### Ендпоінти

| Метод    | Шлях                     | Тіло запиту | Відповідь |
|----------|--------------------------|-------------|-----------|
| `GET`    | `/api/departments/`      | —           | `200`, масив кафедр, відсортований за `name` |
| `POST`   | `/api/departments/`      | об'єкт без `id` | `201`, створена кафедра |
| `PUT`    | `/api/departments/{id}/` | об'єкт без `id`, з усіма обов'язковими полями | `200`, оновлена кафедра |
| `DELETE` | `/api/departments/{id}/` | —           | `204` |

**Особливість видалення:** кафедру, до якої прив'язаний хоча б один викладач або курс, видаляти не можна. У такому разі сервер повертає `409` з полем `detail`.

### Приклад

`POST /api/departments/`
```json
{
  "name": "Кафедра біології",
  "description": "Молекулярна біологія, біохімія, генетика.",
  "email": "biology@ukma.edu.ua"
}
```

Відповідь `201`:
```json
{
  "id": 1,
  "name": "Кафедра біології",
  "description": "Молекулярна біологія, біохімія, генетика.",
  "email": "biology@ukma.edu.ua"
}
```

## Ресурс «Викладачі»: `teachers`

### Поля

| Поле         | Тип     | Обмеження |
|--------------|---------|-----------|
| `id`         | integer | лише читання |
| `first_name` | string  | обов'язкове, до 100 символів |
| `last_name`  | string  | обов'язкове, до 100 символів |
| `position`   | string  | обов'язкове, одне з: `professor`, `associate_professor`, `senior_lecturer`, `assistant` |
| `email`      | string  | необов'язкове, валідний email або порожній рядок |
| `department` | integer | обов'язкове, `id` існуючої кафедри |

Значення `position` бекенд зберігає як є, переклад робить фронтенд:
`professor` — професор, `associate_professor` — доцент, `senior_lecturer` — старший викладач, `assistant` — асистент.

### Ендпоінти

| Метод    | Шлях                  | Тіло запиту | Відповідь |
|----------|-----------------------|-------------|-----------|
| `GET`    | `/api/teachers/`      | —           | `200`, масив викладачів, відсортований за `last_name` |
| `POST`   | `/api/teachers/`      | об'єкт без `id` | `201`, створений викладач |
| `PUT`    | `/api/teachers/{id}/` | об'єкт без `id`, з усіма обов'язковими полями | `200`, оновлений викладач |
| `DELETE` | `/api/teachers/{id}/` | —           | `204` |

Якщо `department` не існує або `position` не з переліку, сервер повертає `400` з помилкою на відповідному полі.

**Особливість видалення:** викладача, який веде курси, видалити можна. У його курсах поле `teacher` стає `null`.

### Приклад

`POST /api/teachers/`
```json
{
  "first_name": "Олена",
  "last_name": "Коваленко",
  "position": "associate_professor",
  "email": "o.kovalenko@ukma.edu.ua",
  "department": 1
}
```

Відповідь `201`:
```json
{
  "id": 1,
  "first_name": "Олена",
  "last_name": "Коваленко",
  "position": "associate_professor",
  "email": "o.kovalenko@ukma.edu.ua",
  "department": 1
}
```

## Ресурс «Курси»: `courses`

### Поля

| Поле          | Тип             | Обмеження |
|---------------|-----------------|-----------|
| `id`          | integer         | лише читання |
| `title`       | string          | обов'язкове, до 200 символів |
| `description` | string          | необов'язкове, може бути порожнім рядком |
| `credits`     | number          | обов'язкове, кредити ЄКТС, від `1` до `15` включно, крок `0.5`. У відповіді повертається числом, наприклад `4.0` |
| `department`  | integer         | обов'язкове, `id` існуючої кафедри |
| `teacher`     | integer або `null` | необов'язкове, `id` існуючого викладача або `null` |

### Ендпоінти

| Метод    | Шлях                 | Тіло запиту | Відповідь |
|----------|----------------------|-------------|-----------|
| `GET`    | `/api/courses/`      | —           | `200`, масив курсів, відсортований за `title` |
| `POST`   | `/api/courses/`      | об'єкт без `id` | `201`, створений курс |
| `PUT`    | `/api/courses/{id}/` | об'єкт без `id`, з усіма обов'язковими полями | `200`, оновлений курс |
| `DELETE` | `/api/courses/{id}/` | —           | `204` |

Якщо `credits` поза діапазоном або `department` чи `teacher` не існують, сервер повертає `400` з помилкою на відповідному полі.

### Приклад

`POST /api/courses/`
```json
{
  "title": "Загальна генетика",
  "description": "Класична та молекулярна генетика.",
  "credits": 4,
  "department": 1,
  "teacher": 1
}
```

Відповідь `201`:
```json
{
  "id": 1,
  "title": "Загальна генетика",
  "description": "Класична та молекулярна генетика.",
  "credits": 4.0,
  "department": 1,
  "teacher": 1
}
```
